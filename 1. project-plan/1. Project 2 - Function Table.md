**Function Input/Output Table**

Every function in the program: what it takes in, what it gives back, and who calls it. Functions are grouped by part, in the order the data flows. Types are C++. "Helper" means the function is used only inside its own part.

**Choices made in this table (approve or change before coding)**

1. **Named bundles for data passed between parts.** A C++ `struct` is a named group of values, like one row of a spreadsheet. Five of them are listed below: pipeline settings, pipeline output, one lookup run, results record, and check report. They only give names to things the part docs already describe.
2. **Two outputs through a filled-in variable.** `pickQuestionsToPlant` and `buildCorpus` each hand back two things. A C++ function returns one thing, so the second is a variable the caller passes in for the function to fill (passed "by reference," marked with `&`).
3. **Errors are thrown, not returned.** If a file can't be opened, `readCsv` throws an exception: it stops and passes a message up to whoever called it. The command-line program catches it, prints the usage line and the message, and exits with a nonzero code. The GUI catches it and shows the message.
4. **New function: `makeStructure`.** It gives back a brand-new, empty structure of the kind asked for, held in a `std::unique_ptr`. That's a C++ holder that deletes the structure automatically once nothing holds it anymore, which is how "let the structure be destroyed" happens. Measurement needs a fresh structure for every build run, and the GUI has to keep the current structure alive between redraws. This does both.
5. **New command-line function: `measureStructure`.** It does measurement's "How the caller uses them" steps 1 to 6 for one structure in one go. The GUI does the same steps one call per redraw instead.
6. **The correctness check is split into four helpers plus one main function**, one per step of its doc, so each step can be tested alone.
7. **Times are `double`, in milliseconds.**
8. **The GUI rows are a suggestion for Will.** He can organize the GUI's own functions however he likes. Only the calls it makes into the shared parts are fixed.
